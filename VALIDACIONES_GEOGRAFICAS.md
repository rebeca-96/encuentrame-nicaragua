## 2. MODELO DE DATOS Y RESTRICCIONES DE INTEGRIDAD

### 2.1 Entidad `Department` ([entities.py](file:///c:/Users/User/Documents/Valor IA/EncuentrameNicaragua/backend/app/models/entities.py))
- `id`: UUID v4, Clave Primaria.
- `name`: `VARCHAR(100)`, No nulo, Único (`index=True`).
- `code`: `VARCHAR(10)`, No nulo, Único (`index=True`).
- `type`: `VARCHAR(32)`, Valores permitidos: `"department"` o `"autonomous_region"`.
- `latitude`: `FLOAT`, Rango válido: `10.70 <= lat <= 15.10`.
- `longitude`: `FLOAT`, Rango válido: `-87.70 <= lon <= -82.50`.
- `is_active`: `BOOLEAN`, Por defecto `True` (Desactivación lógica/Soft Delete).

### 2.2 Entidad `Municipality` ([entities.py](file:///c:/Users/User/Documents/Valor IA/EncuentrameNicaragua/backend/app/models/entities.py))
- `id`: UUID v4, Clave Primaria.
- `department_id`: UUID v4, Clave Foránea (`departments.id`, `index=True`).
- `name`: `VARCHAR(100)`, No nulo, Indexado.
- `code`: `VARCHAR(15)`, No nulo, Único (`index=True`).
- `latitude`: `FLOAT`, Restricción territorial: `10.70 <= lat <= 15.10`.
- `longitude`: `FLOAT`, Restricción territorial: `-87.70 <= lon <= -82.50`.
- `is_active`: `BOOLEAN`, Por defecto `True`.
- **Restricción de Unicidad Compuesta:**  
  `UniqueConstraint("department_id", "name", name="uq_department_municipality_name")` impide nombres duplicados dentro de un mismo departamento.

## 3. MECANISMO DE CARGA INICIAL IDEMPOTENTE ([seed_geography.py](file:///c:/Users/User/Documents/Valor IA/EncuentrameNicaragua/backend/app/core/seed_geography.py))
- La función `seed_nicaragua_geography(db)` verifica la existencia de cada departamento por código o nombre antes de insertar.
- Si el registro ya existe, actualiza sus metadatos (coordenadas oficiales e integridad de tipo) sin duplicar filas.
- Ejecuciones repetidas devuelven exactamente `{departments_count: 17, municipalities_count: 153}` sin alterar claves primarias foráneas vinculadas a reportes existentes.
- Se ejecuta automáticamente durante el arranque de FastAPI si la tabla `departments` se encuentra vacía.

## 4. VALIDACIONES APLICADAS EN API Y ESQUEMAS PYDANTIC

1. **Rango de Coordenadas de Nicaragua:**
   - Todo punto de departamento o municipio es validado contra la función `validate_nicaragua_coordinates`:
     $$\text{Latitud} \in [10.70^\circ\text{N}, 15.10^\circ\text{N}], \quad \text{Longitud} \in [-87.70^\circ\text{O}, -82.50^\circ\text{O}]$$
   - Valores fuera de dicho cuadrante son rechazados con `HTTP 422 Unprocessable Entity`.

2. **Coherencia Geográfica en Reportes (`ReportCreate`):**
   - El validador cruzado compara el municipio seleccionado contra la lista oficial devuelta por `get_municipalities(department)`.
   - Si se envía un municipio que no pertenece al departamento (ej. Managua + Condega), el sistema bloquea la creación con `HTTP 422`.

3. **Control de Acceso Basado en Roles (RBAC):**
   - Endpoints de creación y modificación territorial (`POST /locations/departments`, `PATCH /locations/departments/{id}`, `POST /locations/municipalities`, `PATCH /locations/municipalities/{id}`) exigen autenticación como administrador (`require_admin`).
   - Peticiones anónimas o de usuarios ciudadanos son rechazadas con `HTTP 401 Unauthorized` o `HTTP 403 Forbidden`.
